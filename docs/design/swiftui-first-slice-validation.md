# SwiftUI first slice — validation

Validated October 10, 2026 with Xcode 26.4 / Swift 6.3 and an iPhone 17 Pro simulator running iOS 26.4. The project retains the existing iOS 17 deployment baseline.

## Passed

- App builds against the local GymAndAIKit package; the shared scheme also builds the UI-test target.
- Ten Swift package tests: contract decoding and replay handling; workout display switching without session mutation; cancellation of a delayed demo start after pause/end; explicit resume after rest; missing/stale HR; event-envelope type consistency; bounded JPEG-frame extraction and recovery after oversized input.
- Native simulator workout journey: Today → positioning → Reps/Camera → pause/rest → end/recap → Today. Camera view keeps the coach caption and Pause/End controls accessible. Largest accessibility text keeps workout controls accessible without shrinking text.
- Native integration with the actual local FastAPI server: create an isolated test session, attach the phone, deliver a recorded fixture observation through REST, render its rep through WebSocket, show missing camera feed honestly, and confirm pause/resume/end transitions.
- Existing backend simulator validates all six input fixtures. These are fixture tests, not exercise-model accuracy measurements.
- Interactive mockup: switch views without resetting reps, continue simulated counting while Camera is selected, freeze counting on pause, fit 320px width, and run without JavaScript errors.
- Visually inspected mockup screenshots and native simulator screenshots. Updated the app title placement and pinned controls/camera coaching caption after inspection.

## Boundaries

- Camera preview client accepts MJPEG; a real webcam publisher is not present in the backend yet. The app shows unavailable rather than false live video. The client has not been validated against the team's physical webcam.
- Demo movement and its camera illustration are explicitly simulated. Recorded fixture observations in the backend integration test do not establish model performance.
- Phone camera capture, live Watch delivery, microphone commands, ElevenLabs assets, personalized planner, and persisted history are later integrations. iPhone HealthKit authorization, speech synthesis, and an in-memory last-session summary are implemented.
- No physical iPhone/AirPods or physical-device signing checks have been performed. A development team is configured; select a unique bundle identifier if required to run on a phone.

Native images are in `native/`; v2 mockup images are `gym-ai-reps-view-v2.png` and `gym-ai-camera-view-v2.png`. The original design board is retained.

## First 3D companion — Pip

- Installed Blender 5.2.1 and built an editable procedural Pip source, approximately 18,756 triangles. The 421 KB USDZ retains separate body/arm/foot/ring objects and uses charcoal with #0097B2 material base color. The transparent preview is 768 × 768 RGBA; alpha ranges from 0 to 255.
- The native RealityKit renderer runs in non-AR mode with no camera session. Today, coaching, Rest, Recap, and completed Progress use Pip. Idle, speech-linked coaching, short celebration, and rest motion are implemented. Speech delegate callbacks track the current utterance; stop/mute/background clear speaking state.
- Model and reflection resources load asynchronously; each visible view clones the cached source. Hidden or backgrounded views dismantle their scene and cancel updates. Attachment generations prevent an obsolete load from removing a newly restored scene. Model failure uses the transparent preview. Reduce Motion keeps a still neutral 3D pose.
- Signed simulator build and six UI tests pass on iPhone 17 Pro / iOS 26.4: loaded-model tap/return, fallback with workout start, background/tab restoration, Reduce Motion with rest/recap, camera/reps/rotation/pause/end, and large-text control access. Ten existing package tests also pass. iOS 17 compatibility is compile-checked; an iOS 17 runtime is not installed here.
- The initial celebration assertion missed the short transient state because UI automation waited until the animation finished. The final check verifies the tap returns to Ready with the model loaded and button enabled. It does not assert intermediate animation frames.
- Separate native frame comparisons verify actual idle motion: two mascot-region captures 1.2 seconds apart differ (mean RGB differences approximately 1.37/2.10/2.34). With Reduce Motion forced, the same region is pixel-identical. These are rendering checks, not an FPS or battery benchmark.
- Visually inspected the Blender preview and native Today/Rest captures. Native reference files use the `pip-` prefix under `native/`. Source and rebuild instructions are in `models/pip/`.
- No physical iPhone was connected. Device material appearance, thermal performance, real video coexistence, speech/voice interruptions, music ducking, and AirPods routing require the manual check in `ios/README.md`. Atlas and Flex remain subsequent model work.
